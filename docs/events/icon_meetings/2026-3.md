## Reports

### C2SM (Michael Jähn, Matthieu Leclair, Mikael Stellio, Alitzel Macías)

MJ mentions that to receive the invitation for this meeting, one needs to subscribe to the [C2SM ICON mailing list](../../models/icon/index.md#mailing-list) on the C2SM landing page.

MJ welcomes everyone and shares the [latest news about ICON from C2SM :material-download:](https://polybox.ethz.ch/index.php/s/2ddZ43CLpEx83cK){:target="_blank"}.

CZ asks about the reason behind the name `--gpus-per-node` in the recent node sharing changes on [Säntis](../../hpc/cscs/santis.md); MK replies that it was the most convenient choice. He also confirms that `--gres-flags=allow-task-sharing` must be passed to `srun` (not in the `#SBATCH` block). CSCS is still working on the accounting, so that users only get billed for the GPUs they actually use; this is expected to be ready by the end of the year.

MaL mentions that when selecting NUMA nodes, one has to explicitly ask the system which socket was assigned, to make sure that the binding is correct.

CK asks where to report issues with ICON, as this is currently not very clear. MaL answers that it will get better once the repositories are unified on `icon/icon`. TS suggests flagging issues internally first and letting C2SM report them, since otherwise no one is clearly responsible. MaL says that this needs to be discussed further, especially given the upcoming switch to nightly-only CI testing. CK's specific issue only occurred with 24 nodes, which is why the bug was not caught by the CI.

Regarding the issue with the [HWSD :material-open-in-new:](https://www.fao.org/soils-portal/data-hub/soil-maps-and-databases/harmonized-world-soil-database-v20/en/){:target="_blank"} (Harmonized World Soil Database) soil data in [EXTPAR](../../tools/extpar.md), CZ says that he has a dataset that MS can compare with the current one to evaluate its correctness. MA is also interested in this dataset from CZ.
